01 / What it solves

Small decisions are still language problems.

A support message can be easy for a person to understand but hard to capture with fixed rules. A full generated response gives the app more text to interpret before it can act.

Jev takes state + typed questions and returns answers with probabilities. The application decides what to do with them.
Choice

Which option?

Pick one defined category, such as billing or technical support, and see the probability across options.

Score

How much?

Place something on an ordered scale, such as low to critical urgency.

Noul

Is it true?

Get a yes probability for a focused condition, such as whether a person should review a ticket.

02 / Fit and limits

Use Jev for judgment. Give exact work to exact tools.

The useful shape is a semantic question with known answers. Jev 1.13 has documented weak spots, so the surrounding code matters.

Good fit for Jev
  • Choosing among known categories
  • Grading a clearly defined dimension
  • Checking whether a condition is supported by text
  • Sending uncertain cases to another step
Use another tool for
  • Writing or open-ended explanation: generative LLM
  • Math, counting, dates, and exact rules: code
  • Permissions and security decisions: policy code
  • Long chains of reasoning: a reasoning model or a simpler workflow

Keep the state relevant and treat model output as a signal. TypeSafe also warns that adversarial text can steer Jev; important actions need testing, safeguards, and an uncertainty path.

05 / Implemented POC · resume evaluation

A reviewed requirement travels through two evaluations.

The app compares documented resume evidence with the job description. It does not make a hiring decision.

  1. 1 · Input

    Job description + resume

    The sample texts are preloaded. A user can replace either one.

  2. ↓
  3. 2 · Shared extraction

    OpenAI proposes requirements from the JD

    Each retained requirement needs an exact quote from the job description. The resume does not create new requirements.

  4. ↓
  5. 3 · Human review

    A person checks what will be judged

    Review the wording and evidence needed. Resolve any importance marked “unspecified.”

    RequirementEvaluation criteriaImportanceJev primitive
  6. ↓
  7. 4a · Jev

    Typed judgments

    Uses Noul, Score, or Choice for each requirement. A separate Choice selects a resume excerpt from candidates.

    4b · OpenAI

    Structured evaluation

    Assesses the same reviewed requirements and provides a concise explanation.

  8. ↓
  9. 5 · App code and display

    Verify evidence. Calculate the range.

    Code accepts only exact resume quotes, weights mandatory items twice as much as preferred items, and widens the match range for uncertain items. Results appear side by side.

Example: the JD prefers Azure as the primary recent production platform. The resume says production deployments used AWS ECS. Choice identifies AWS; the evidence quote is checked against the resume.

JD quote → requirement → evidence

Keep the roles clear

Jev supplies the judgment. The system stays in charge.

Use Jev when the question is focused and the possible answers are known. Let people review important criteria, let code enforce exact rules, and use a generative model when the task needs new text.
